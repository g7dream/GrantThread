# API contract v1

JSON API uses camelCase keys, integer minor units and ISO date-only strings. Error shape: `{ "error": "human-readable message", "code": "stable_code" }`. Auth: Bearer token. Local base `http://127.0.0.1:8000/api`; Vite proxies `/api`. AWS base configured through `VITE_API_URL`.

`GET /health` -> `{status, mode, agentConfigured}`; `GET /session` -> `{user:{id,name,role,organisationId,organisationName},mode}`. Local-only `POST /demo/login {identity:"brightpath"|"harbour"|"northstar"}` -> `{token,user}`. `POST /demo/reset {confirm:true}` clears this local synthetic dataset and sessions except current session. Cloud reset via operator script only.

`GET /portfolio` -> `{organisation, grants:Grant[], decisions:Proposal[], totals:{currency,awardMinor,allocatedMinor,expenseMinor,uniqueActivities}, requirements:Requirement[], jobs:Job[]}`.
Grant `{id,name,funderName,funderOrgId,granteeOrgId,currency,awardMinor,allocatedMinor,fundingMode,deadline,template,version,readiness:{evidenced,total,ready,missing:string[]}}`.
`GET /grants` -> Grant[]; `GET /grants/:id` -> `{grant,requirements,expenses,activities,evidence,reports}`.

`POST /response-estimates {grantId,submittedDate:"YYYY-MM-DD"}` is a read-only grantee calculator. It requires a grant in the signed-in organisation and rejects future or malformed dates. Returns `{grantId,grantName,funderName,simulated:true,asOfDate,submittedDate,elapsedDays,sampleCount,comparableSampleCount,typicalTotalDays:number|null,historicalRangeDays:{low,high}|null,remainingDays:{low,typical,high}|null,expectedDates:{earliest,typical,latest}|null,status:"estimated"|"insufficient_history"|"beyond_history",historyDays:number[],method:"conditional-empirical-quartiles",unit:"calendar_days"}`. Low/high are nearest-rank 25th/75th percentiles; typical is the median rounded up. Only simulated completed reviews taking longer than the elapsed wait enter the remaining-time calculation. Fewer than three comparable samples returns no countdown. UTC dates, no mutation, no agent job or real funder history. See [response estimates](RESPONSE_ESTIMATES.md).

`GET /expenses` -> Expense[]; `POST /expenses/import {csv,commit?:boolean}` -> `{rows,errors,warnings,imported,proposalIds}`. Columns `expense_id,description,amount,currency,date,grant_id,allocation_amount`; repeated expense IDs permitted for split allocation only when original facts match. Preview default. Currency EUR only in synthetic portfolio. Unknown grants or malformed/ambiguous records block commit.

`GET /evidence` -> Evidence[]; `POST /evidence {name,content,grantIds:string[],expenseId?:string,kind:"invoice"|"payment_proof"|"activity"|"agreement", replacesId?:string}` local text convenience; all clients use `POST /evidence/upload-intent {name,contentType,size,grantIds,expenseId?,kind,replacesId?}` -> `{id,uploadUrl,method,headers}`; upload binary; `POST /evidence/complete {id}` -> `{evidence,job}`. `GET /evidence/:id` -> evidence with text and pages; `GET /evidence/:id/download` -> bytes. Evidence `{id,name,kind,version,sha256,pageCount,grantIds,expenseId,createdAt,status,excerpt,text?,pages?}`. Evidence remains pending until approved link.

`GET /proposals` -> Proposal[]; `POST /proposals/:id/apply {expectedVersion:number,allocations?:[{grantId,amountMinor}]}`; `POST /proposals/:id/reject {expectedVersion}`. Proposal `{id,kind:"allocation"|"evidence_link",title,reason,status,version,inputVersion,expenseId?,evidenceId?,sourceRefs:[{evidenceId,version,page,excerpt}],before,after,excessMinor?,createdAt}`. Applying pending invalid split requires corrected allocation values. Stale inputs return 409; refresh via `POST /proposals/:id/recompute`.

`POST /proposals/batch-apply {proposals:[{id,expectedVersion}]}` atomically applies up to 20 evidence connections against the same current input version. Stale members abort the whole batch. GET projections mark pending proposals/drafts stale after input changes. Evidence uploads, CSV commits and authorised approvals schedule a new reconciliation when configured; unavailability stays explicit.

CSV preview rows include separate `expenseAmountMinor` and `allocationMinor`, along with expense facts, `grantId` and row number. Cloud source-download endpoints return an authorised 302 to an expiring private S3 GET URL; local mode returns bytes. This avoids Lambda response limits for 5 MB sources.

`GET /jobs` -> Job[]; `POST /jobs {grantId?:string}` -> Job; `GET /jobs/:id` -> Job. Job `{id,status,engine:"strands-bedrock",createdAt,finishedAt?,message,toolEvents:[{name,at,result}],inputVersion,actorId,organisationId}`. No model configured means `unavailable`, not success.

`GET /reports` -> Report[]; `POST /reports {grantId}` -> Report; `GET /reports/:id` -> Report; `GET /reports/:id/pdf` -> PDF; `GET /reports/:id/manifest` -> JSON file. Report `{id,grantId,grantName,funderName,template,version,inputVersion,createdAt,status,readiness,currency,awardMinor,allocatedMinor,expenses:[{description,amountMinor}],activities:[{id,title,participants,date}],narrative,sourceRefs,availableAttachments:[{id,name,version,kind}],sharedSnapshotId?}`.
`POST /reports/:id/share {expectedVersion,attachmentIds:string[],confirmOriginals:boolean}` -> Snapshot. Only ready/current report can share. Original attachments require explicit selection and confirmation. `GET /shared-reports` -> Snapshot[]; `GET /shared-reports/:id` -> Snapshot; `/pdf`, `/manifest`, `/attachments/:evidenceId` under that snapshot. Snapshot `{id,reportId,grantId,grantName,recipientOrgId,recipientName,granteeName,version,publishedAt,report:Report,attachments:[{id,name,version,kind}],clarifications:Clarification[]}`; report excludes internal warnings and unrelated allocations.

`GET /clarifications` -> Clarification[]; `POST /clarifications {snapshotId,question,sourceRef?:{evidenceId,version,page}}` funder only -> Clarification; `POST /clarifications/:id/respond {message}` grantee only; `POST /clarifications/:id/resolve {}` funder only after response. Clarification `{id,snapshotId,grantName,question,status:"open"|"answered"|"resolved",createdAt,sourceRef?,messages:[{actorName,role,message,at}]}`.

Seed grant IDs `digital-belonging`, `community-makers`, `youth-skills`, `volunteer-support`; organisation IDs `brightpath`, `harbour`, `northstar`, `riverbend`; expense IDs `venue`, `printing`, `facilitator`, `kits`, `insurance`. Fixture venue allocations pending only; other canonical allocations total 420000 minor units. Proposed venue 70000+50000 exceeds 100000 by 20000. Approved correction 50000+50000 results in 170000/310000/40000.

## Backend integration hooks (root owns service/repository)

`backend/grantthread/repository.py`: `get_repository()` returns repository with `read(org_id)->dict` and `mutate(org_id, callback)->any`. Callback mutates aggregate atomically and returns result. Aggregate has `version`, dictionaries `grants,expenses,evidence,proposals,reports,jobs,snapshots,clarifications`, lists `requirements,activities,audit`. Mutation increments `version`; `factVersion` increments only on confirmed financial/evidence changes. Cloud table partition key `pk` stores `ORG#<id>` with JSON payload and optimistic version; membership `MEMBER#<subject>` payload is server-managed identity.

`backend/grantthread/service.py`: `Service(identity, repository=None)`; methods `list_requirements(grant_id=None)`, `read_evidence(evidence_id)`, `calculate_allocations(grant_id=None)`, `check_report_readiness(grant_id)`, `save_review_proposal(proposal:dict)`, `assemble_report_draft(grant_id)`, `list_evidence()`, `get_job(job_id)`, `update_job(job_id, **fields)`. All methods enforce server identity scope. Worker receives only `{organisationId,jobId}` and gets immutable actor identity from persisted job. Persist derived outputs via service, never direct financial writes. `run_job(organisation_id,job_id)` should be defined by agent in `worker.py`; local job runner will call it asynchronously. `storage.py` owns `get_storage()` with `put(key,bytes,content_type)`, `get(key)->bytes`, `presign_put(key,content_type)->str|None`. Root implements storage.
