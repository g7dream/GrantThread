# Release checklist

Use `PROGRESS.md` for current implementation status. This checklist stays unchecked until the corresponding release evidence exists.

- [ ] Build and relevant domain/integration tests pass on the final revision; attach actual commands/results.
- [ ] G1-G5 in [EVALUATION.md](EVALUATION.md) have recorded results and failures resolved or disclosed.
- [ ] Required credentials and judge identities established through approved private configuration.
- [ ] Hosted UI uses the intended API origin, Cognito callback/logout URLs and HTTPS.
- [ ] Genuine Strands job completed against the chosen account, model and region; save redacted tool-event evidence.
- [ ] Funder snapshot and every download route pass the cross-organisation checks.
- [ ] Two reports open and values match independently calculated fixture expectations.
- [ ] Tested desktop/narrow layout, keyboard journey and relevant accessibility behavior are documented.
- [ ] Frontend ZIP contains public assets only and its base path matches the destination.
- [ ] Existing hosting files are backed up; rollback path and stack teardown procedure reviewed.
- [ ] Public repository includes functioning source, lockfiles, setup, architecture, fixture licence notices and a recognised root licence.
- [ ] Review [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md); remove secrets and local data from staged files/history.
- [ ] Fill [Devpost draft](submission/DEVPOST.md) with actual URLs, verification and disclosure.
- [ ] Record a working public video; inspect its final runtime and remove all placeholders from published copy.
- [ ] Replace or remove the unmeasured benchmark section in publication materials; never imply measurement happened.
- [ ] Obtain any still-required external publication authorisation after the concrete material is ready.
- [ ] Recheck [official rules](submission/RULES_CHECK.md), final entrant details, judge access duration and submission receipt.
- [ ] Publish the three optional Builder posts only after screenshots/run results exist and publication is authorised; record actual URLs.
- [ ] Freeze the release revision, keep a recovery copy and monitor actual AWS costs during judging.

Stop release for a permission leak, corrupted financial result, unsupported factual report claim, unusable export or missing genuine agent evidence. Cut optional polish before those gates. Do not represent local completion as deployed completion.
